복습

폴더 · 전역 · 프로젝트

폴더와 전역 설정 개념을 다시 짚어야 이어지는 설정 파일 이야기가 매끄럽게 읽힌다.

VS Code 폴더 관리프로젝트별 작업 폴더 지정
  • 프로젝트마다 폴더를 만들어 따로 관리한다.
  • 작업 폴더를 지정한 뒤 그 안에서 사용한다.
클로드 코드 세션계정 공유, 대화는 로컬별 분리
  • 계정 하나로 여러 곳에서 접속할 수 있다.
  • 로컬에서 동작해 대화 내용은 컴퓨터마다 따로 저장된다.
전역 설정 위치C드라이브 사용자 폴더 아래 .claude
  • 이 폴더의 파일을 지우고 다시 설치할 수 있다.
작업 폴더 생성 원칙폴더 먼저 생성, 그 안에서 시작
  • 클로드를 쓸 폴더는 자유롭게 정할 수 있다.
  • 다만 폴더를 먼저 만들고 그 안에서 시작한다.
CLAUDE.md규칙 파일, /init으로 생성
  • md 파일에 지시사항을 적는다.
  • /init을 실행하면 새 환경에서 CLAUDE.md가 생성된다.
  • 폴더마다 따로 두면 프로젝트별로 다른 규칙이 적용된다.
질문폴더별 CLAUDE.md 규칙 각각 적용 여부
  • 가능하다. 프로젝트별로 다르게 적용된다.

요약 VS Code와 클로드는 폴더 단위로 관리하며, 전역 설정은 .claude 한 곳에 모이고 CLAUDE.md는 폴더마다 규칙이 따로 적용된다.

설정

settings.json 3계층

settings.json으로 클로드의 특정 동작을 통제하며, 여기서 프로젝트는 작업 폴더를 뜻한다.

01전역 설정모든 프로젝트 공통 바탕 설정
    ~/.claude/settings.json
    • 모든 프로젝트에 적용되는 바탕 설정이다.
    02프로젝트 설정다 같이 쓰는 것
      .claude/settings.json
      • 회사 공지문과 비슷해 이 프로젝트를 쓰는 사람 전원에게 똑같이 적용된다.
      03로컬 설정나만 쓰는 것
        .claude/settings.local.json
        • 내 책상 서랍 메모와 비슷해 이 컴퓨터에서만 적용된다.
        • 다른 사람 컴퓨터에는 영향을 주지 않는다.
        • 우선순위는 전역, 프로젝트, 로컬 순이며 아래쪽이 위쪽을 덮어쓴다.
        만드는 법위치 지정 없으면 전역에 생성
        • 프로젝트에 두려면 위치를 지정해 생성을 요청한다.
        • 생성된 파일은 VS Code 탐색기에 나타나고 더블클릭하면 편집할 수 있다.
        주요 키 4가지model · permissions · env · hooks
        • model은 이 프로젝트의 기본 모델을 지정한다.
        • permissions는 허용(allow)과 차단(deny) 규칙 목록이다.
        • env는 환경 변수를 주입한다.
        • hooks는 정해진 시점에 명령을 실행한다(5회차 범위).
        실습 흐름rm 차단 규칙 추가 확인
        • "rm 차단 규칙 추가해줘"라고 요청한다.
        • "note.txt 삭제해줘"를 입력하면 차단 메시지가 뜬다.
        • settings.json 내용에서 규칙이 반영됐는지 확인한다.
        • 작업 폴더 밖 파일은 쓰기가 제한되고, 상위 폴더 접근은 별도 허가가 필요하다.
        • 대화 데이터를 학습에 쓰지 않게 하려면 claude.ai 설정의 데이터 개인정보 보호 항목에서 끈다.

        요약 전역, 프로젝트, 로컬 3계층이며 아래쪽이 위를 덮는다. 주요 키는 model, permissions, env, hooks 넷이다.

        권한

        권한 모드 4종

        Shift+Tab을 누르면 권한 모드가 바뀌는데, 필기 용어와 자료 용어가 달라 아래는 자료 기준으로 정리했다.

        01일반 모드편집 · 명령 매번 승인
        • 파일 편집과 명령 실행 모두 매번 승인해야 한다.
        02편집 자동 승인 모드accept edits
        • 파일 편집은 자동 승인되어 코드 변경이 곧바로 진행된다.
        • 터미널 명령은 여전히 승인이 필요하다.
        03플랜 모드읽기 · 탐색만
        • 편집과 실행은 할 수 없다.
        • 계획을 세운 뒤 승인을 받아야 실행된다.
        04욜로 모드승인 절차 생략
          claude --dangerously-skip-permissions
          • 승인 절차를 전부 생략한다.
          • 종료는 /exit 또는 Ctrl+C로 한다.
          • 위쪽 방향키로 이전 명령을 다시 불러온다.
          필기 대조Auto 모드 ≠ 욜로 모드
          • 필기의 "Auto 모드"는 수정, 명령 실행, 여러 단계 작업을 알아서 진행하는 것을 뜻한다.
          • 욜로 모드는 권한 확인 자체를 끄는 별개 개념이다.
          • 모드 구성은 버전마다 바뀔 수 있으니 헷갈리면 클로드에게 직접 물어본다.

          요약 Shift+Tab으로 전환하며, 일반에서 편집 자동 승인, 플랜, 욜로까지 4단계다.

          명령어

          기본 명령어와 /config

          명령어가 헷갈리면 /help로 전체 목록을 바로 확인할 수 있다.

          기본 명령어 5개/init · /clear · /model · /login · /logout · /help
          • /init은 새 환경에서 CLAUDE.md를 만든다.
          • /clear는 대화를 초기화한다.
          • /model은 모델을 바꾼다.
          • /login과 /logout은 계정을 로그인하거나 로그아웃한다.
          • /help는 전체 명령어 목록을 보여준다.
          /config 3탭Status · Config · Usage
          • Status에서는 버전, 세션, 계정, 모델, IDE(코드 편집 프로그램) 연결, MCP(외부 서비스 연결 표준) 상태를 확인한다.
          • Config에서는 Auto-compact, Thinking mode, Theme 같은 세부 동작을 켜고 끈다.
          • Usage에서는 세션과 주간 사용량, 리셋 시각을 본다.
          Todos · Task 목록내장 도구 3종
          • TaskCreate와 TaskList, TaskUpdate 세 가지다.
          • 상태는 pending에서 in_progress를 거쳐 completed로 흐른다.
          ○○○ 작업을 todo 리스트를 세워서 순차적으로 진행해줘
          • practice 폴더를 만들고 readme.txt를 작성한 뒤 트리를 출력하는 3단계를 순서대로 실행한다.

          요약 명령어 전체는 /help로 보고, /config는 3탭이며 Task 상태는 3단계로 흐른다.

          확장

          모델 선택 · 웹검색 · 클로드 인 크롬

          작업 성격에 맞는 모델을 고르고 필요하면 웹검색을 쓰며, 브라우저를 연결하면 화면 작업까지 맡길 수 있다.

          모델 4종Haiku · Sonnet · Opus · Fable
          • Haiku는 가장 빨라 간단하고 많은 작업에 쓴다.
          • Sonnet은 속도와 성능이 균형 잡혀 있어 기본으로 추천한다.
          • Opus는 복잡한 작업과 에이전트 코딩의 기본값이다.
          • Fable은 성능이 가장 높아 가장 어려운 문제에 쓴다.
          웹검색필요 판단 시 자동 실행
          • 따로 지시하지 않아도 최신 정보가 필요하면 스스로 검색한다.
          ○○○ 주제 웹조사해줘
          • 명시적으로 요청할 때 쓰는 문구다.
          오늘 기준 최근 7일 이내에 발행된 AI 에이전트 관련 기사나 글을 웹조사해줘. 각 항목의 주요 내용과 실제 출처 링크도 함께 정리해줘
          • 실습에 쓰는 프롬프트다.
          Claude in Chrome브라우저 연결 확장
          • 가능한 작업은 라이브 디버깅, 디자인 검증, 웹앱 테스트, 로그인이 필요한 웹앱 접근(구글 문서, Gmail, Notion), 데이터 추출, 반복 작업 자동화, 세션 녹화다.
          • 지원 브라우저는 Chrome과 Edge다.
          • Brave와 Arc는 지원 대상이 아니다.
          • 크롬 웹스토어에서 확장 프로그램을 설치한 뒤 claude --chrome을 실행하거나 /config에서 기본 활성화하고, /mcp에서 chrome for claude를 Enable한다.

          요약 모델은 4단계이고, 웹검색은 자동으로 판단하며, Claude in Chrome은 Chrome과 Edge에서만 쓴다.

          세션

          세션 이어가기와 되돌리기

          대화가 끊겨도 다시 이어갈 수 있고, 실수했을 때는 되돌릴 수도 있다.

          01터미널에서 이어가기--resume · --continue
            claude --resume
claude --continue
            • --resume은 선택기에서 이전 세션을 고른다.
            • --continue는 가장 최근 대화를 바로 이어간다.
            02대화 도중 전환/resume · /rename
              /resume
/rename
              • /resume은 대화 중 다른 세션으로 전환한다.
              • /rename은 세션 이름을 지정해 이후 찾기 쉽게 한다(예 여행계획, 쇼핑몰 리뷰분석).
              03되돌리기/rewind, Esc 두 번
                /rewind
                • 대화만 되돌릴지, 파일 변경까지 되돌릴지 선택할 수 있다.
                • Ctrl+Z처럼 실수를 복구할 때 쓴다.
                정리위치별 구분
                • --resume과 --continue는 터미널에서 쓴다.
                • /resume은 대화 도중에 쓴다.

                요약 터미널에서는 --resume이나 --continue, 대화 중에는 /resume이나 /rename을 쓰고 복구는 /rewind로 한다.

                문맥

                컨텍스트 관리

                컨텍스트가 얼마나 찼는지 확인한 뒤 압축할지 비울지 고르면 된다.

                캐시이미 처리한 정보 재사용 저장
                • 시스템이 이미 읽은 내용을 재활용한다.
                • 단기기억에 해당한다.
                웹 페치지정 주소 내용 직접 가져와 읽기
                • 지정한 URL 내용을 가져와 읽는 동작이다.
                명령어 4개/context · /compact · /clear · Auto Compact
                • /context는 컨텍스트 사용량을 그림으로 보여줘 압축 판단의 근거가 된다.
                • /compact는 대화를 압축한 뒤 이어간다.
                • /clear는 컨텍스트를 완전히 비운다.
                • Auto Compact는 95% 근처에서 자동으로 압축한다.
                질문/compact와 /clear 실무 기준
                • /compact는 남길 내용을 클로드가 판단한다(주제를 지정해도 결과는 클로드가 정한다).
                • 남겨야 할 내용은 CLAUDE.md에 적어두면 압축 후에도 유지된다.
                자동 압축 기준점 조정settings.json의 env
                  CLAUDE_AUTOCOMPACT_PCT_OVERRIDE
                  • 실습에서는 20%로 낮춰 자동 압축을 확인한 뒤 원래대로 되돌린다.

                  요약 캐시는 재사용을 위한 저장이며, /context로 확인한 뒤 /compact나 /clear를 고르고 기준점은 env로 조정한다.

                  병렬

                  백그라운드 작업

                  대화와 분리된 작업 공간이라 다른 일을 병렬로 진행할 수 있다.

                  Foreground실행 → 완료까지 대기
                  • 완료까지 기다린다.
                  • 기본 타임아웃은 120초이며 넘으면 강제로 종료된다.
                  Background실행 → 즉시 ID(작업 구분 번호) 반환 → 별도 진행
                  • 비동기로 진행된다.
                  • 전환은 Ctrl+B를 누르거나 클로드에게 요청하면 된다.
                  타임아웃 넘기는 방법 2가지
                  • Ctrl+B로 백그라운드로 전환한다.
                  • settings.json에서 bash 타임아웃을 연장하며, 18,000,000ms가 5시간이다.
                  목록 확인/tasks · /bashes · Ctrl+F
                  • /tasks는 백그라운드 작업 목록을 관리하며, 상태는 실행 중, 완료, 보류 중으로 나뉜다.
                  • /bashes는 백그라운드에서 실행 중인 셸 명령 목록이다.
                  • Ctrl+F는 모든 백그라운드 에이전트를 종료한다.
                  • 필기의 /bashes는 셸 명령 목록이고 수업에서 다룬 것은 /tasks로, 서로 다른 대상이다.
                  활용 패턴 3가지
                  • 오래 걸리는 작업을 백그라운드로 넘기고 다른 일을 진행한다.
                  • 개발 서버를 실행한 채 코드 수정을 병렬로 진행한다.
                  • 에러 로그를 감시하거나 메시지 수신을 대기한다.
                  • 실습에서는 count.md에 1초 간격으로 1~20을 기록하는 스크립트를 백그라운드로 실행하고, 같은 작업을 Foreground로 시작한 뒤 Ctrl+B로 전환해 /tasks로 진행을 확인한다.

                  요약 Foreground는 120초까지 기다리고 Background는 즉시 반환하며, 타임아웃은 Ctrl+B나 env 연장으로 넘긴다.

                  막힐 때

                  설정 · 세션 증상 10개

                  화면에 뜬 문구로 찾는다. 안 풀리면 수업 전에 연락해 화면을 함께 본다.

                  설정settings.json을 고쳤는데 반영 안 됨
                  • 쉼표·따옴표·중괄호 하나만 틀려도 파일 전체 무시
                  • 저장 → 클로드 종료 → 재실행. 그래도 안 되면 진단
                  • claude doctor
                  설정전역과 프로젝트에서 다르게 동작
                  • 정상. 로컬 → 프로젝트 → 전역 순으로 아래쪽이 우선 3계층
                  • 프로젝트 폴더 .claude 안의 settings.local.json부터 확인
                  권한파일 고칠 때마다 승인 요청
                  • Shift+Tab으로 편집 자동 승인 모드 전환
                  • 매번 확인하고 싶으면 일반 모드 유지
                  권한플랜 모드에서 아무것도 안 고침
                  • 정상. 플랜 모드는 읽기·계획만
