설치

프로그램 3종

오늘은 VS Code·클로드 데스크톱·옵시디언 세 프로그램만 설치하면 되고, 파워셸은 윈도우에 이미 있어 따로 설치하지 않는다.

  • code.visualstudio.com/download → Windows → 받은 파일 실행
  • 동의 체크 → 다음
  • 추가 작업 선택: "Code(으)로 열기" 2줄 체크
  • 설치 → 완료
  • VS Code 창 열림
02한국어 팩메뉴 한국어화. 확장 1개 설치
  • Ctrl+Shift+X → 검색 Korean
  • 맨 위 항목 Install
  • 우하단 재시작 단추 클릭
  • 메뉴 한국어 표시
03클로드 데스크톱 설치클로드 대화 프로그램. 안에 Code 단추
  • claude.ai/download → Windows → 설치
  • 기존 클로드 계정 로그인
  • 왼쪽에 Chat · Code 표시
  • Code 미표시 = 유료 구독 아님
04옵시디언 설치메모 프로그램. 클로드 결과물 열람 화면

  • 계정 생성 화면 → 건너뛰기
  • 첫 화면 표시. 여기서 대기 → 5번

업무 폴더 하나를 만들어 VS Code·클로드·옵시디언이 함께 쓰게 한다.

  • 빈 곳 우클릭 → 새로 만들기 → 폴더
  • 이름 업무
  • 문서 안에 업무 폴더

  • 00_우체통 미분류 메모
  • 01_자료 참고 자료
  • 02_프로젝트 진행 중인 일
  • 99_시스템 규칙 · 기록
  • 업무 안에 폴더 4개, 숫자 순 정렬
07VS Code로 열기VS Code는 파일이 아니라 폴더 단위로 열기
  • 탐색기 → 업무 우클릭 → Code(으)로 열기
  • "작성자를 신뢰합니까" → 예
  • VS Code 왼쪽 최상단 업무, 아래 폴더 4개
08파일 1개 생성.md = 글자 파일 표시

  • 이름 00_할일.md → Enter
  • 본문 아무 글 → Ctrl+S
  • 왼쪽 목록에 00_할일.md
09아래 칸 열기파워셸. 글자 명령 창, 1회차 설치 명령 입력 자리
  • Ctrl+`(숫자 1 왼쪽 키) → 아래 칸 표시
  • 아래 글 복사 → 붙여넣기 → Enter

  • 업무 선택
  • 왼쪽에 00_할일.md + 폴더 4개(8번 파일 그대로)

  • 톱니 → 편집기 → 맞춤법 검사 → 끔

  • 새 세션 → 폴더 선택 → 업무
  • 아래 글 붙여넣기 → Enter → 허용 창 → 허용

  • 생성 파일이 옵시디언·VS Code 양쪽에 뜨면 세 프로그램이 한 폴더를 본다는 뜻이다

  • 아래 글 붙여넣기 → Ctrl+S
# 작업 규칙

- 새 문서는 00_우체통에 만든다

  • 클로드 새 세션 → "규칙 파일 읽었어?" → 4줄 답변
  • 같은 지적을 두 번 받으면 그 자리에서 규칙 1줄을 추가한다

요약 옵시디언·클로드·VS Code가 업무 폴더 하나를 공유하고 규칙 파일까지 만들어 오늘 준비를 마쳤다.

메모 프로그램 생략 시 경로

옵시디언 없이 VS Code와 클로드 두 개만으로도 오늘 실습을 마칠 수 있다.

건너뛸 단계옵시디언 관련 3개
  • 4번(옵시디언 설치) · 10번(볼트로 열기) · 11번(옵시디언 설정)은 건너뛴다
  • 1~3 · 5~9 · 12~13번은 그대로 진행한다
파일 읽는 자리VS Code 미리보기 또는 메모장
  • VS Code 왼쪽에서 .md 파일 클릭 → Ctrl+Shift+V를 누르면 제목·목록이 꾸며진 미리보기가 뜬다
  • 미리보기를 끄려면 탭을 닫고, 원문을 고치려면 그냥 클릭한다
  • 탐색기에서 파일을 더블클릭하면 메모장이 열리고 원문 그대로 보인다
12번 성공 기준옵시디언 칸 대신 VS Code 칸
  • 클로드가 만든 파일이 VS Code 왼쪽에 나타나면 두 프로그램이 같은 폴더를 본다는 뜻이다
차이옵시디언 유무
  • 옵시디언이 있으면 메모끼리 연결([[이름]])하고 전체 검색도 되고 읽기 화면도 따로 생긴다
  • 옵시디언이 없어도 파일 편집·미리보기만으로 수업 진행에는 지장이 없다
  • 나중에 옵시디언을 추가할 땐 4·10·11번만 실행하면 되고 파일·폴더는 그대로다

요약 옵시디언은 선택 사항이고, 없으면 VS Code 미리보기(Ctrl+Shift+V)로 대신할 수 있다.

                  백그라운드 작업

                  대화와 분리된 작업 공간이라 다른 일을 병렬로 진행할 수 있다.

                  Foreground실행 → 완료까지 대기

                  • 기본 타임아웃 120초, 초과 시 강제 종료
                  Background실행 → 즉시 ID(작업 구분 번호) 반환 → 별도 진행
                  • 비동기로 진행된다.
                  • 전환은 Ctrl+B를 누르거나 클로드에게 요청하면 된다.
                  타임아웃 넘기는 방법 2가지
                  • Ctrl+B로 백그라운드 전환
                  • settings.json에서 bash 타임아웃을 연장하며, 18,000,000ms가 5시간이다.
                  목록 확인/tasks · /bashes · Ctrl+F
                  • /tasks는 백그라운드 작업 목록을 관리하며, 상태는 실행 중, 완료, 보류 중으로 나뉜다.
                  • /bashes는 백그라운드에서 실행 중인 셸 명령 목록이다.
                  • Ctrl+F는 모든 백그라운드 에이전트를 종료한다.
                  • 필기의 /bashes는 셸 명령 목록이고 수업에서 다룬 것은 /tasks로, 서로 다른 대상이다.
                  활용 패턴 3가지
                  • 오래 걸리는 작업을 백그라운드로 넘기고 다른 일을 진행한다.
                  • 개발 서버를 실행한 채 코드 수정을 병렬로 진행한다.
                  • 에러 로그를 감시하거나 메시지 수신을 대기한다.
                  • 실습에서는 count.md에 1초 간격으로 1~20을 기록하는 스크립트를 백그라운드로 실행하고, 같은 작업을 Foreground로 시작한 뒤 Ctrl+B로 전환해 /tasks로 진행을 확인한다.

                  요약 Foreground는 120초까지 기다리고 Background는 즉시 반환하며, 타임아웃은 Ctrl+B나 env 연장으로 넘긴다.

                  • model 이 에이전트가 쓸 모델

                  훅

                  이벤트에 자동으로 붙는 내 스크립트

                  • 코드 자동 정리는 파일을 수정한 뒤 정렬 도구를 자동으로 실행한다.
                  • 등록 위치 settings.json의 hooks 키, 시점별 명령어 기재

                  MCPAI가 외부 서비스를 직접 다루는 표준 방식
                  • USB-C에 비유하면 기기 종류와 무관하게 하나의 규격으로 연결된다는 뜻이다.
                  • 클로드가 노션 · 구글 드라이브 · 지메일 직접 읽고 쓰기 가능
                  • 클로드 · ChatGPT · 커서 등 주요 도구가 지원하는 공개 표준
                  MCP 없을 때수동 3단계
                  • 내용 복사 → 클로드에 붙여넣기 → 결과 다시 입력
                  MCP 있을 때한 마디로 처리
                  • 예시 "노션 회의록 정리해줘" → 클로드가 직접 처리

                  요약 MCP는 외부 서비스를 직접 연결하는 표준이며, 없으면 수동으로 복붙하고 있으면 한 마디로 끝난다.

                  claude mcp add로 서버 등록

                  claude mcp add --transport stdio [이름] -- npx ...
                  03관리목록 · 삭제
                  claude mcp list
claude mcp remove [이름]
                  • 대화 안에서는 /mcp로 연결된 서버 목록 확인, 인증 · 관리
                  적용 범위3단계
                  • local 현재 프로젝트

                  • user 내 PC 전체
                  • 3회차 설정 파일 세 계층과 같은 구분

                  요약 등록은 claude mcp add(http/stdio)로 하고 관리는 list·remove로 하며, 범위는 local·project·user 세 단계다.

                  질문

                  채팅창과 터미널 패널, 네 갈래

                  채팅창과 옆 터미널 패널은 서로 다른 창이라 명령어가 넘어가지 않는다.

                  질문채팅창에 명령어를 바로 입력할 수 있는지
                  • 불가, 채팅 입력은 전부 클로드에게 가는 메시지라 셸로 미도달
                  • 셸 명령은 옆 터미널 패널에 직접 입력 또는 클로드 답변 bash 코드블록 실행 버튼 사용
                  질문터미널 패널은 무엇인지
                  • 순수 파워셸, 클로드가 실행되지 않아 슬래시 명령 인식 불가
                  • /mcp 입력 시 CommandNotFoundException
                  • 화면 셸은 2개로, 패널은 사람이 입력하고 클로드는 읽기만 하며 클로드 작업용 셸은 따로 있다.
                  • 변수 · 현재 폴더 상태는 비공유, 파일 · 결과물은 공유
                  질문패널에서 클로드 실행 방법
                  • 슬래시 빼고 claude만 입력, 슬래시 붙이면 파워셸이 경로로 인식
                  • 실행 파일 사용자 폴더\AppData\Roaming\npm\claude.ps1, PATH 등록
                  • 대화형 화면이라 실행 버튼 불가, 직접 입력
                  질문그렇게 실행한 세션이 별도인지
                  • 별도 세션, 대화 맥락 분리
                  • 파일 · CLAUDE.md · 훅 · 스킬 · 메모리 폴더는 공유, 대화 내용만 분리
                  • 같은 파일 동시 수정 시 나중 저장분이 덮어씀
                  • 세션 간 메시지 전달 가능, 받는 쪽은 사용자 턴으로 수신 · 하던 작업 중단
                  • 예약 실행 · 원격 세션은 메시지 주고받기 불가

                  요약 채팅창은 클로드로만 가고 터미널 패널은 순수 파워셸이며, claude는 슬래시 없이 실행하고 세션은 파일을 공유하되 대화는 분리된다.

                  00VS Code 재시작가장 흔한 해결책. 절반 이상 이걸로 해결

                  • 작업 파일은 그대로 유지, 대화만 새로 시작. 이어가려면 claude --continue
                  • 그래도 같으면 컴퓨터 재시작. 설치 직후 명령 미인식은 재시작으로 대부분 해결
                  01claude 찾을 수 없음CommandNotFoundException류 메시지

                  • 그래도 같으면 npm install -g @anthropic-ai/claude-code 재실행 후 00번
                  • 슬래시 붙여 /claude로 입력하면 파워셸이 경로로 인식해 실패, 슬래시 제외, claude만 입력

                  • 파워셸 관리자 권한으로 열어 입력, 물음에 A 입력 → 00번

                  04클로드 멈춘 것 같음작업 중 vs 무응답 구분

                  • 새로 시작해도 파일·CLAUDE.md는 유지, 지켜야 할 내용은 CLAUDE.md에 기록(4회차 내용)
                  06파일 잘못 수정되돌리기

                  • 대화만 되돌릴지, 파일 변경까지 되돌릴지 선택 가능. 실수 복구용 Ctrl+Z에 해당
                  07허락 창 반복자동 승인 모드 전환

                  • --dangerously-skip-permissions는 권한 확인 자체를 끔, 꼭 필요한 순간에만 사용 후 평소 모드 복귀
                  08파일 없음·엉뚱한 곳 생성작업 폴더 확인

                  알아두면 유익한 것

                  슬라이드에는 없지만 실습 중 실제로 자주 부딪히는 것들을 모았다.

                  01description 역할자동 호출 판단 근거
                  • "회의록 정리"처럼 실제로 말할 낱말을 넣으면 슬래시 명령 없이도 발동
                  02pip 실패 대처python -m pip 대체
                  • pip는 Python 기본 내장. 사용자 폴더명이 한글이거나 PATH(실행 파일 찾는 경로 목록)가 잘못된 경우 python -m pip install pillow로 대부분 해결

                  • Pillow 기본 글꼴은 영문 전용

                  • 클로드에게 "한글 폰트로 바꿔줘" 요청 시 이 경로를 찾아 적용
                  04플러그인의 정체스킬·훅·MCP 설정 파일과 동일

                  05설치 범위 3계층settings.json 3계층과 대응
                  • User·Project·Local은 전역·프로젝트·로컬과 같은 구분이다
                  • 팀 공유는 Project, 개인 실험은 Local
                  06LSP·commit의 뜻편집기 표준 규약과 Git 저장 동작
                  • LSP(Language Server Protocol)는 편집기가 "이 변수의 정의는 어디"를 묻는 표준 규약이며, VS Code 자동완성이 이 원리로 동작한다. 코드 작업이 없으면 건너뛰어도 된다
                  • commit은 Git에서 지금 상태를 이름 붙여 저장하는 동작이다
                  07gh scope 7종권한별 허용 범위
                  • repo 저장소 읽기·쓰기, delete_repo 삭제, workflow 자동 실행 편집, gist 코드 조각 공유, read:org 조직 조회, admin:public_key SSH 키 등록, write:packages 패키지 업로드
                  • 삭제 권한은 꼭 필요할 때만 부여
                  08PAT 취급 주의비밀번호급 문자열
