AI에이전트1 · 5~6회차

서브 에이전트·훅·MCP, 외부 연결 3갈래

수업일 2026-09-05 · 범위 5~6회차(서브 에이전트·훅 / MCP) · 정리 오영선 멘토

에이전트

특정 역할 전담, 서브 에이전트

역할 하나를 통째로 맡기면 메인 대화와 따로 돌아가 결과만 돌려준다.

서브 에이전트특정 역할만 맡는 전담 에이전트
  • 별도 대화 공간에서 독립 실행, 결과만 메인 에이전트에 전달
  • 메인 대화창 맥락과 별개로 동작
  • 역할 설명이 요청과 맞으면 클로드가 자동 위임, 사람이 매번 지목 불필요
  • 설정 파일 위치 .claude/agents/ 폴더
  • /agents 명령어로 목록 조회·생성·수정
설정 파일 구조4개 키
name: report-writer
description: 보고서를 작성합니다
tools: Read, Write, Bash
model: sonnet
  • name 에이전트 이름
  • description 역할 설명, 클로드가 넘길 위치를 고르는 기준
  • tools 이 에이전트가 쓸 수 있는 도구 목록
  • model 이 에이전트가 쓸 모델

요약 서브 에이전트는 독립 실행하는 전담 에이전트이며, .claude/agents/ 설정 파일 4개 키로 만들고 /agents로 관리한다.

만들기

클로드가 대신 쓰는 설정, 병렬 실행

설정 파일을 직접 쓰지 않고 프롬프트 한 줄로 에이전트 여러 개를 한 번에 돌릴 수 있다.

01만들기/agents → Create new agent → Generate with Claude
  • 역할 설명만 입력하면 설정 · 시스템 프롬프트 자동 작성
02저장 위치범위 2단계
  • ~/.claude/agents/ 저장 → 이 컴퓨터 모든 프로젝트에서 사용
  • 프로젝트 폴더 안 저장 → 그 프로젝트 한정
03병렬 실행프롬프트 한 줄로 여러 에이전트 동시 실행
  • 예시 프롬프트
시장 조사, 데이터 정리, 보고서 초안을 별도 에이전트로 동시에 진행해줘
  • 비개발자도 보고서 작성·데이터 정리·번역 전담 에이전트로 바로 써먹을 수 있다.
실습만들기 1건 · 병렬 실행 1건
  • 실습1 만들기: claude 실행 → /agents → Create new agent → Generate with Claude → "보고서 요약 전담 에이전트" 설명 입력 → 저장
  • 실습2 병렬 실행: 오늘 날씨 조사·뉴스 요약·일정 정리를 에이전트 3개로 동시에 진행한다.
  • 각각 독립 실행, 결과만 메인에 보고되는지 확인

요약 에이전트는 /agents의 Generate with Claude로 만들고 저장 위치로 사용 범위를 정하며, 병렬 실행은 프롬프트 한 줄로 끝낸다.

훅

이벤트에 자동으로 붙는 내 스크립트

도구 실행이나 응답 완료 같은 순간마다 내가 만든 스크립트가 자동으로 움직인다.

훅도구 실행 · 응답 완료 같은 이벤트 감지 시 내 스크립트 자동 실행
  • 위험 명령 차단은 삭제 명령을 실행하기 전에 자동으로 막아 준다.
  • 작업 완료 알림은 응답이 끝나는 순간 PC로 알려 준다.
  • 코드 자동 정리는 파일을 수정한 뒤 정렬 도구를 자동으로 실행한다.
  • 등록 위치 settings.json의 hooks 키, 시점별 명령어 기재
  • 3회차 설정 파일 네 계층 중 5회차로 남겨 둔 자리

요약 훅은 settings.json hooks 키에 등록하는 자동화이며, 차단·알림·정리 세 가지 용도로 쓴다.

이벤트

18개 시점, 차단 9 · 관찰 9

훅이 감지하는 시점은 18개이고, 그중 절반만 실제로 진행을 막을 수 있다.

차단 가능 9종exit 2 → 실행 정지
  • PreToolUse · 도구 실행 직전
  • UserPromptSubmit · 프롬프트 처리 전
  • PermissionRequest · 권한 요청 시점
  • Stop · 응답 완료 직전
  • SubagentStop · 서브 에이전트 종료 시
  • TeammateIdle · 팀원 대기 상태 전환 전
  • TaskCompleted · 작업 완료 표시 전
  • ConfigChange · 설정 파일 변경 시
  • WorktreeCreate · 워크트리 생성 전
관찰 9종기록 · 알림 용도, 진행 차단 불가
  • SessionStart · 세션 시작 · 재개 시
  • InstructionsLoaded · CLAUDE.md 읽은 뒤
  • PostToolUse · 도구 실행 성공 뒤
  • PostToolUseFailure · 도구 실행 실패 뒤
  • Notification · 알림 발생 시
  • SubagentStart · 서브 에이전트 시작 시
  • PreCompact · 대화 압축 전
  • SessionEnd · 세션 종료 시
  • WorktreeRemove · 워크트리 삭제 뒤

요약 훅 시점은 18개이며 차단 가능 9개와 관찰 9개로 나뉘고, 차단 조건은 exit 2다.

흐름

프롬프트 → 도구 실행 → 종료 코드 판정

프롬프트를 보내면 도구가 실행되기 전후로 훅이 끼어들어 진행 여부를 가른다.

흐름프롬프트 → 훅 → 도구 → 훅 → 응답
  • 사용자 프롬프트 → UserPromptSubmit → PreToolUse → 도구 실행(Read, Write, Bash 등) → PostToolUse → Stop
종료 코드exit 2 → 차단, exit 0 → 계속
  • exit 2 → 차단, stderr에 적은 메시지가 클로드에게 그대로 전달
  • exit 0 → 계속 진행, 자동 정렬 · 알림 같은 부가 작업만 하고 종료
  • 쉽게 쓰려면 직접 작성하지 않고 "위험 명령 차단 훅 추가해줘"라고 요청해 클로드가 쓰게 한다.
실습Stop 이벤트에 PC 알림 훅 걸기
  • 요청 프롬프트
settings.json에 Stop Hook을 추가해줘. BurntToast 모듈이 설치되어 있는지 먼저 확인하고,
없으면 Install-Module로 설치한 뒤, powershell.exe -NoProfile -Command 형식으로
Import-Module BurntToast 후 New-BurntToastNotification으로 작업 완료 알림을 띄워줘
  • claude 실행 → 위 프롬프트 입력
  • 질문 후 응답 종료 시 알림 확인
  • BurntToast 모듈 없으면 클로드가 Install-Module로 먼저 설치
  • 응용하면 팝업 대신 기록 파일에 한 줄 남기도록 구조는 그대로 두고 실행 명령만 바꿀 수 있다.

요약 흐름은 프롬프트→PreToolUse→도구→PostToolUse→Stop 순서이며, exit 2면 차단되고 exit 0이면 진행한다.

MCP

외부 서비스 연결 표준

MCP를 연결하면 복사·붙여넣기 없이 한 마디로 외부 서비스를 시킬 수 있다.

MCPAI가 외부 서비스를 직접 다루는 표준 방식
  • USB-C에 비유하면 기기 종류와 무관하게 하나의 규격으로 연결된다는 뜻이다.
  • 클로드가 노션 · 구글 드라이브 · 지메일 직접 읽고 쓰기 가능
  • 클로드 · ChatGPT · 커서 등 주요 도구가 지원하는 공개 표준
MCP 없을 때수동 3단계
  • 내용 복사 → 클로드에 붙여넣기 → 결과 다시 입력
MCP 있을 때한 마디로 처리
  • 예시 "노션 회의록 정리해줘" → 클로드가 직접 처리

요약 MCP는 외부 서비스를 직접 연결하는 표준이며, 없으면 수동으로 복붙하고 있으면 한 마디로 끝난다.

설치

claude mcp add로 서버 등록

claude mcp add 한 줄이면 원격 서버든 내 PC 실행형이든 등록된다.

01HTTP 방식transport http, 원격 서버, 수업자료 권장
claude mcp add --transport http [이름] [URL]
02stdio 방식내 PC에서 직접 실행
claude mcp add --transport stdio [이름] -- npx ...
03관리목록 · 삭제
claude mcp list
claude mcp remove [이름]
  • 대화 안에서는 /mcp로 연결된 서버 목록 확인, 인증 · 관리
적용 범위3단계
  • local 현재 프로젝트
  • project 팀 공유
  • user 내 PC 전체
  • 3회차 설정 파일 세 계층과 같은 구분

요약 등록은 claude mcp add(http/stdio)로 하고 관리는 list·remove로 하며, 범위는 local·project·user 세 단계다.

연동

트리바고 · 캔바 · 윅스 · 노션

트리바고·캔바·윅스·노션을 등록하면 채팅창에서 바로 검색하고 만들고 배포한다.

트리바고숙소 검색
claude mcp add --transport http trivago https://mcp.trivago.com/mcp
  • 인증 절차 생략, 설치 후 바로 사용
  • 국가·도시·날짜·인원 기준으로 검색하고 가격·위치·리뷰를 비교하며 예산·등급·편의시설로 거른다.
  • 실습: 강남 지역 1박 2명 숙소를 검색한 뒤 예산 10만원 이하로 다시 검색한다.
캔바디자인 제작
claude mcp add --transport http canva https://mcp.canva.com/mcp
  • 등록 후 /mcp에서 canva 선택 → Authenticate → 브라우저 로그인
  • /mcp에 canva connected가 뜨면 연결이 끝난 것이다.
  • 실습: AI 에이전트 소개 프레젠테이션을 만들어 PDF로 내보내고 첫 슬라이드 제목을 바꾼다.
윅스웹사이트 배포
claude mcp add wix --transport http https://mcp.wix.com/mcp
  • 구글 계정 로그인, 별도 가입 불필요
  • 사이트 생성 · 템플릿 적용 · 콘텐츠 편집 · 배포
  • 실습: 의류 판매 쇼핑몰 콘셉트 사이트를 만들어 배포하고 메인 페이지에 배너를 추가한다.
노션문서 자동화
claude mcp add --transport http notion https://mcp.notion.com/mcp
claude mcp list
  • 등록은 1회, 이후 인증만 하면 사용
  • 인증은 /mcp에서 notion 선택 → Authenticate → 브라우저 인증 페이지 → URL 신뢰 체크 → 계속하기 → 로그인
  • 인증도 1회, 다음 세션에서 연결 유지
  • 실습: 회의록 페이지를 만들고 데이터베이스에 작업 항목을 추가한다.
공통 주의인증 3곳 공통
  • 캔바 · 윅스 · 노션 인증 단계, 수업자료는 claude --dangerously-skip-permissions 실행 안내
  • 권한 확인 전체 해제 모드, 인증 후 평소 모드 복귀 권장

요약 4개 서비스를 등록 명령으로 연결하고, 인증은 /mcp의 Authenticate로 진행한다.

예시

수업자료 대 예시 환경

  • 18종 중 차단 1종 + 관찰 1종부터 시작, 필요할 때 추가

  • 구글 캘린더 · 크롬은 데스크톱 앱 커넥터로 별도 연결
  • 실습 목적이면 노션 하나로 충분, 나머지는 필요할 때 추가

  • 7회차에서는 자주 쓰는 작업 절차를 파일로 저장하는 스킬을 다룬다.
  • 8회차에서는 클로드 데스크톱 앱 사용법을 다룬다.
  • 이 문서에 슬라이드 밖 구두 설명과 실습 중 오류 대응은 없으니 11절(질문)을 참고한다.

요약 예시 환경은 에이전트 3종, 훅 2이벤트, MCP 노션 1개로 구성한다.

질문

채팅창과 터미널 패널, 네 갈래

채팅창과 옆 터미널 패널은 서로 다른 창이라 명령어가 넘어가지 않는다.

질문채팅창에 명령어를 바로 입력할 수 있는지
  • 불가, 채팅 입력은 전부 클로드에게 가는 메시지라 셸로 미도달
  • 셸 명령은 옆 터미널 패널에 직접 입력 또는 클로드 답변 bash 코드블록 실행 버튼 사용
질문터미널 패널은 무엇인지
  • 순수 파워셸, 클로드가 실행되지 않아 슬래시 명령 인식 불가
  • /mcp 입력 시 CommandNotFoundException
  • 화면 셸은 2개로, 패널은 사람이 입력하고 클로드는 읽기만 하며 클로드 작업용 셸은 따로 있다.
  • 변수 · 현재 폴더 상태는 비공유, 파일 · 결과물은 공유
질문패널에서 클로드 실행 방법
  • 슬래시 빼고 claude만 입력, 슬래시 붙이면 파워셸이 경로로 인식
  • 실행 파일 사용자 폴더\AppData\Roaming\npm\claude.ps1, PATH 등록
  • 대화형 화면이라 실행 버튼 불가, 직접 입력
질문그렇게 실행한 세션이 별도인지
  • 별도 세션, 대화 맥락 분리
  • 파일 · CLAUDE.md · 훅 · 스킬 · 메모리 폴더는 공유, 대화 내용만 분리
  • 같은 파일 동시 수정 시 나중 저장분이 덮어씀
  • 세션 간 메시지 전달 가능, 받는 쪽은 사용자 턴으로 수신 · 하던 작업 중단
  • 예약 실행 · 원격 세션은 메시지 주고받기 불가

요약 채팅창은 클로드로만 가고 터미널 패널은 순수 파워셸이며, claude는 슬래시 없이 실행하고 세션은 파일을 공유하되 대화는 분리된다.

슬래시 명령어 직접 만들기

자주 쓰는 지시를 슬래시 명령 하나로 줄여 반복 없이 부를 수 있다.

스킬 정의파일 하나가 슬래시 명령어 하나
  • 자주 시키는 일을 한 줄 명령으로 축약이 목적
파일 위치프로젝트 전용 · 컴퓨터 전체 전용 구분
  • .claude/skills/<이름>/SKILL.md에 두면 그 프로젝트 폴더에서만 쓴다
  • ~/.claude/skills/<이름>/SKILL.md에 두면 이 컴퓨터의 모든 프로젝트에서 쓴다
호출 방법직접 호출 · 자동 호출 2가지
  • /스킬이름 직접 호출, /스킬이름 [인수] 값 전달
  • 관련 대화가 등장하면 클로드가 자동으로 호출하며, 판단 기준은 description이다
SKILL.md 구조머리말 description + 지침 본문
  • 위 세 줄은 머리말이고, description 한 줄에 스킬이 하는 일을 적는다
---
description: 이 Skill이 하는 일
---
# 지침
클로드에게 줄 지시사항을 마크다운으로 작성
  • 아래 본문은 업무 지시서 형식의 마크다운으로 쓴다
  • 기본 제공 스킬 예시로 /simplify /batch /debug /loop가 있다

요약 기능 말하기·조사와 코드 요청·스킬화 요청 세 단계를 따르면, 원하는 기능이 라이브러리를 거쳐 명령어로 이어지는 흐름을 대응표 4개 예시로 확인할 수 있다.

당황할 때 대처법

막히는 상황 대부분은 순서대로 시도하면 5분 안에 풀린다.

00VS Code 재시작가장 흔한 해결책. 절반 이상 이걸로 해결
  • 파일 → 종료(Windows Alt+F4)로 창 전부 닫기, 창 하나만 닫으면 잔존 가능
  • 다시 열고 같은 작업 폴더에서 터미널에 claude 새로 실행
  • 작업 파일은 그대로 유지, 대화만 새로 시작. 이어가려면 claude --continue
  • 그래도 같으면 컴퓨터 재시작. 설치 직후 명령 미인식은 재시작으로 대부분 해결
01claude 찾을 수 없음CommandNotFoundException류 메시지
  • 터미널 창 닫고 새로 열기(설치 후 연 터미널은 새 명령 모름)
  • 그래도 같으면 npm install -g @anthropic-ai/claude-code 재실행 후 00번
  • 슬래시 붙여 /claude로 입력하면 파워셸이 경로로 인식해 실패, 슬래시 제외, claude만 입력
02스크립트 실행 차단윈도우 보안 정책
Set-ExecutionPolicy RemoteSigned
  • 파워셸 관리자 권한으로 열어 입력, 물음에 A 입력 → 00번
03슬래시 명령 오류claude 실행 밖에서 입력
  • /mcp /plugin 등은 claude 실행 중인 대화 안에서만 동작
  • 터미널에 바로 입력하면 파워셸이 모르는 명령이라 오류. claude 먼저 실행 후 그 안에서 입력
04클로드 멈춘 것 같음작업 중 vs 무응답 구분
  • 점이 움직이거나 Thinking이 뜨면 작업 중이며, 파일이 많으면 1~2분 걸린다
  • 중단은 Esc 1회(현재 동작만 중단, 대화 유지)
  • 완전 종료는 /exit 또는 Ctrl+C 2회
  • 백그라운드 작업은 /tasks에서 진행 확인
  • 무반응이면 00번
05답이 엉뚱함문맥 포화
  • /context로 사용량 확인
  • /compact로 요약 또는 /clear로 새로 시작
  • 새로 시작해도 파일·CLAUDE.md는 유지, 지켜야 할 내용은 CLAUDE.md에 기록(4회차 내용)
06파일 잘못 수정되돌리기
  • Esc 2회 또는 /rewind
  • 대화만 되돌릴지, 파일 변경까지 되돌릴지 선택 가능. 실수 복구용 Ctrl+Z에 해당
07허락 창 반복자동 승인 모드 전환
  • Shift+Tab으로 모드를 전환하며, 편집 자동 승인 모드에서는 파일 수정 확인을 생략한다
  • --dangerously-skip-permissions는 권한 확인 자체를 끔, 꼭 필요한 순간에만 사용 후 평소 모드 복귀
08파일 없음·엉뚱한 곳 생성작업 폴더 확인
  • VS Code 파일 → 폴더 열기로 작업 폴더가 열려 있는지 확인
  • 터미널 줄 맨 앞 경로가 그 폴더인지 확인, 아니면 터미널 닫고 새로 열기
  • 파일을 탐색기에서 대화창으로 끌어다 놓으면 경로 정확히 전달
09pip·npm 빨간 글씨설치 오류 대응

  • pip는 Python 기본 내장. 사용자 폴더명이 한글이거나 PATH(실행 파일 찾는 경로 목록)가 잘못된 경우 python -m pip install pillow로 대부분 해결

  • Pillow 기본 글꼴은 영문 전용
  • Windows는 C:\Windows\Fonts\malgun.ttf(맑은 고딕) 사용
  • 클로드에게 "한글 폰트로 바꿔줘" 요청 시 이 경로를 찾아 적용

  • User·Project·Local은 전역·프로젝트·로컬과 같은 구분이다
  • 팀 공유는 Project, 개인 실험은 Local
06LSP·commit의 뜻편집기 표준 규약과 Git 저장 동작
  • LSP(Language Server Protocol)는 편집기가 "이 변수의 정의는 어디"를 묻는 표준 규약이며, VS Code 자동완성이 이 원리로 동작한다. 코드 작업이 없으면 건너뛰어도 된다
  • commit은 Git에서 지금 상태를 이름 붙여 저장하는 동작이다
07gh scope 7종권한별 허용 범위
  • repo 저장소 읽기·쓰기, delete_repo 삭제, workflow 자동 실행 편집, gist 코드 조각 공유, read:org 조직 조회, admin:public_key SSH 키 등록, write:packages 패키지 업로드
  • 삭제 권한은 꼭 필요할 때만 부여
08PAT 취급 주의비밀번호급 문자열

09클로드 -p 모드claude -p도 비대화형
  • 다른 프로그램·스킬이 AI를 부품처럼 부를 때 쓰는 방식
  • "bash로 agy -p 호출 스킬" 성립 근거

11정적 사이트 배포GitHub Pages로 무료 배포
