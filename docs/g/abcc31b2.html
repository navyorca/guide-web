Who

이런 분께 추천합니다

디자인 완성도보다 "작동하고 배포된 내 서비스 하나"를 목표로 하는 분을 위한 과정입니다.

코딩을 한 번도 배워본 적 없는 분
문법을 먼저 외우지 않습니다. Claude Code에 말로 요청하고, 만들어진 결과를 눈으로 확인하며 감을 잡아가는 방식으로 진행합니다.
AI가 짜준 코드를 직접 리뷰하고 싶은 분
만들어주는 대로 쓰기만 하지 않습니다. HTML·CSS를 읽고 설명할 수 있는 수준까지 함께 익혀, AI 코드를 검토할 줄 아는 사람이 됩니다.
실제로 보여줄 작업물이 필요한 분
시안 이미지가 아니라 실제 접속 가능한 URL로 남는 결과물입니다. 면접이나 미팅에서 바로 보여줄 수 있는 작업물이 됩니다.
아이디어를 직접 검증해보고 싶은 분
로그인, 데이터 저장·수정·삭제까지 갖춘 완성형 구조라 초기 아이디어를 검증하는 마이크로 서비스로도 바로 활용할 수 있습니다.

01 · 도구랑 친해지기 (1~6회차)

1환경 세팅 시작▾
Claude Code는 말로 시키면 코드를 대신 짜주는 AI 비서입니다. 이 비서와 함께 쓸 프로그램(Claude Code·Node·Cursor)을 설치하고 정상 실행 여부를 확인합니다. 아직 제작 단계는 아닙니다.
→ 내 컴퓨터에 필요한 도구 3가지 준비 완료
2GitHub 기초▾
GitHub은 내가 만든 코드를 저장해두는 온라인 보관함입니다. 계정을 만들고 내 프로젝트용 빈 저장소를 1개 생성한 뒤, 같은 계정으로 배포용 서비스인 Vercel에도 가입합니다.
→ 내 이름의 GitHub 저장소 1개, Vercel 계정 생성 완료
3Supabase 기초▾
Supabase는 서비스에 쌓이는 정보를 저장하는 데이터 창고로, 엑셀 표 여러 장을 관리하는 개념과 유사합니다. 오늘은 계정 생성까지만 진행하고, 실제 표 제작은 이후 회차에서 다룹니다.
→ Supabase 계정 및 빈 프로젝트 1개 생성
4CLAUDE.md 작성▾
CLAUDE.md는 AI 비서가 항상 참고하는 메모장입니다. "개인 포트폴리오 사이트 제작"이라는 사전 정보를 제공하면 이후 코드 정확도가 올라갑니다. 제공 양식에 맞춰 프로젝트를 3줄로 소개하는 글을 작성합니다.
→ CLAUDE.md 초안 1개 (완성도보다 방향성 확인 목적)
5템플릿 탐색 · 주제 확정▾
학원에서 제공하는 템플릿 3~4종을 직접 확인하고 구조와 분위기를 비교합니다. 자기소개와 프로젝트를 함께 소개하는 "개인 포트폴리오 사이트"로 제작 주제를 확정합니다.
→ 제작 주제 확정 — 개인 포트폴리오 사이트
6첫 배포 체험▾
배포란 내 컴퓨터 안에서만 보이던 화면을 인터넷 주소로 누구나 접속 가능하게 올리는 작업입니다. 내용을 채우기 전, 템플릿을 그대로 Vercel에 먼저 배포해보며 "배포는 어렵지 않다"는 경험을 미리 확보합니다.
→ 실제 작동하는 인터넷 주소(URL) 1개 확보

02 · 종이 위에서 설계하기 (7~10회차)

7기획서 작성▾
"자기소개와 프로젝트를 함께 보여주는 개인 포트폴리오 사이트"를 누가, 왜 보게 되는지 A4 한 장 분량으로 정리합니다. 채용 담당자나 방문자가 이 사이트에서 얻는 것이 무엇인지 답할 수 있는 수준이면 충분합니다.
→ 기획서 1장 제작 완료
8기능정의서 작성▾
필요한 기능을 선별해 목록으로 정리합니다. 자기소개 영역, 로그인, 프로젝트 등록·수정·삭제, 프로젝트 상세 보기 정도로 구성하며, 기능이 많을수록 완성 난이도가 올라가므로 5개 이내를 권장합니다.
→ 기능 목록(체크리스트) 제작 완료
9화면 목록 작성▾
앞서 정한 기능별로 필요한 화면을 정리합니다. 메인(자기소개), 프로젝트 목록, 프로젝트 상세, 프로젝트 등록·수정 폼, 로그인·회원가입까지 총 5개 페이지를 도출합니다.
→ 화면 목록표 제작 완료 (페이지명 + 구성 내용)
10첫 화면 생성▾
피그마 수강자는 본인 시안을, 미수강자는 학원 제공 와이어프레임을 AI에 전달해 첫 화면 제작을 요청합니다. Figma MCP는 디자인 파일을 AI가 읽어 코드로 전환해주는 연결 기능입니다.
→ 첫 화면 브라우저 상 구현 확인

03 · 눈에 보이는 화면 완성 (11~18회차)

11HTML·CSS 읽는 법▾
코드 제작이 아닌 "읽기"에 집중하는 회차입니다. 태그·속성·class가 화면 어느 부분과 연결되는지, CSS 선택자가 무엇을 가리키는지 짚어가며 AI가 생성한 폴더·파일 구조까지 함께 훑어봅니다.
→ HTML·CSS 코드를 보고 화면과 연결지어 설명 가능한 수준 확보
12메인 화면 완성▾
자기소개 히어로 영역(이름, 한 줄 소개, 대표 이미지)의 텍스트·이미지를 채워 완성된 화면 형태로 마무리합니다.
→ 메인(자기소개) 페이지 제작 완료
13프로젝트 목록 화면 완성▾
등록될 프로젝트들을 카드 형태로 나열하는 목록 화면을 제작합니다. 이 단계에서는 고정 텍스트로 채운 정적 상태입니다.
→ 프로젝트 목록 화면 제작 완료
14프로젝트 상세 화면 완성▾
목록에서 프로젝트를 클릭했을 때 이동하는 개별 소개 화면을 제작합니다. 프로젝트 설명, 사용 기술, 링크 등이 들어갈 영역을 구성합니다.
→ 프로젝트 상세 화면 제작 완료
15등록·수정 폼 화면 완성▾
프로젝트를 새로 등록하거나 수정할 때 쓰는 입력 폼 화면을 제작합니다. 제목·설명·이미지·사용 기술·링크 입력 항목으로 구성하며, 이 화면이 있어야 이후 저장 기능 작업이 가능해집니다.
→ 프로젝트 등록·수정 폼 화면 제작 완료
16로그인 화면 완성▾
이메일·비밀번호를 입력하는 로그인·회원가입 화면을 제작합니다. 아직 실제 인증 기능은 연결하지 않고, 화면만 먼저 완성합니다.
→ 로그인·회원가입 화면 제작 완료
17컴포넌트화 · QA · 반응형▾
지금까지 만든 5개 화면을 한 번에 정리합니다. 반복 요소는 컴포넌트화로 재사용 가능하게 정리하고, 어색한 부분을 AI에 수정 요청하며, 모바일에서 깨지는 부분(반응형)까지 함께 점검합니다.
→ 전체 화면 정리·다듬기·모바일 대응 완료
18HTML·CSS 심화 읽기▾
강사와 1:1로 지금까지 작성된 정적 화면 코드 전체를 함께 읽으며 점검합니다. 반복되는 태그 패턴과 반응형 처리에 쓰인 CSS까지 짚어보고, 불필요한 코드·네이밍을 정리해 반영합니다.
→ HTML·CSS 코드를 처음부터 끝까지 읽고 설명 가능한 수준 확보

04 · 진짜로 작동하게 만들기 (19~24회차 · 핵심 구간)

19DB 테이블 설계▾
Supabase의 "표"는 엑셀 시트 한 장과 동일한 개념입니다. 제목·설명·대표 이미지·사용 기술·링크·등록일 항목으로 프로젝트 표를 설계하고 실제 생성합니다.
→ Supabase 프로젝트 데이터 표 생성 완료
20데이터 저장 (Create)▾
등록 폼에 입력한 내용이 Supabase 표에 실제 저장되도록 연동 작업을 진행합니다. 저장 버튼 클릭 후 데이터 반영 여부를 직접 확인하는, 전체 구간 중 가장 중요한 회차입니다.
→ 첫 프로젝트 등록(저장) 성공 확인
21데이터 조회 (Read)▾
저장된 프로젝트 데이터를 목록·상세 화면에 실제 연동합니다. 정적으로 채워뒀던 고정 텍스트를 실제 데이터로 교체합니다.
→ 저장된 프로젝트가 목록·상세 화면에 표시 확인
22데이터 수정 (Update)▾
등록된 프로젝트 정보를 다시 수정할 수 있도록 수정 버튼과 저장 기능을 연동합니다.
→ 수정 기능 정상 작동 확인
23데이터 삭제 (Delete)▾
등록된 프로젝트를 삭제하는 기능을 구현합니다. 삭제 전 확인 절차 포함 여부도 함께 점검합니다.
→ 삭제 기능 정상 작동 확인
24CRUD 통합 점검▾
등록·조회·수정·삭제 전체 흐름을 순차 테스트합니다. 강사와 함께 예외 처리(빈 값 입력 등) 여부와 전체 코드 구조를 점검하고 개선 포인트를 반영합니다.
→ CRUD 4가지 전체 정상 작동, 코드 리뷰 완료 — 핵심 구간 완성

05 · 문 잠그고 세상에 내놓기 (25~27회차)

→ 로그인·회원가입 정상 작동 확인

→ 본인 프로젝트만 수정 가능 확인, 보안 점검 체크리스트 통과
