오픈 첫날 걸린 것

2026-10-05 실제 저장 중 확인한 내용과 매뉴얼의 핵심 규칙입니다. 여기부터 봅니다.

  1. 상담예정은 날짜와 시간을 둘 다 넣는다하나라도 비면 내사방문관리 목록에 뜨지 않음
  2. 내사방문관리 [수정]만 하고 끝내지 않는다수정 저장 시 문의DB에 결과메모 빈 상담예정 일지가 새로 생김 → 멘토별문의DB [상담일지]에서 상담예정·날짜·결과메모·상담시간 다시 저장
  3. [상담일지] 저장은 되돌릴 수 없다저장할 때마다 새 일지 1건, 수정 불가, 상담내용 필수
  4. 시간 선택 칸은 위로 올려 본다처음엔 09~11만 보임, 위로 올리면 12~08 있음
  5. 저장이 멈추면 다시 누르지 않는다늦게 처리돼 같은 일지가 두 번 생길 수 있음 → 새로고침 뒤 목록에서 확인
  6. 방문일시 확인은 멘토별문의DB 결과메모로내사방문 목록 일시가 옛 값으로 남는 경우 있음
  7. 학사·개강·교육·환불일지는 한 번에 완성해 저장저장 후 수정·삭제 불가, 면담일지·취업일지만 수정 가능
  8. 구인트라넷 원서는 뉴인트라넷에서 결제 안 됨결제 화면에 원서가 안 보이면 등록처부터 확인
  9. 학적상태와 수강상태는 다른 값학적=사람 단위(재학·휴학 등), 수강상태=과목 단위(수강중·일시중지 등)
  10. 배정은 운영부 원서 확인 뒤에 가능결제 여부와 무관, 사업부배정가능 Y여야 직접 배정, 정규 과목은 개강 4일 뒤 운영부 요청
  11. 특별처리는 유형마다 따로 신청매출·환불 멘토 변경은 그 기간 사업부 수수료대장 마감 전까지, 승인되면 자동 반영
  12. 즐겨찾기는 브라우저마다 따로 저장다른 PC·브라우저에서는 다시 등록

비밀번호를 모르면?
  • 1로그인 화면에서 비밀번호 변경 클릭
  • 2아이디 입력
  • 3임시비밀번호 발급 클릭
  • 4등록된 이메일에서 임시비밀번호 확인
  • 5임시비밀번호로 로그인 후 개인 비밀번호로 변경
비밀번호를 바꾸려면?
  • 1로그인 화면에서 비밀번호 변경 클릭
  • 2아이디·현재 비밀번호 입력
  • 3새 비밀번호·새 비밀번호 확인 입력
  • 4저장 클릭 후 새 비밀번호로 로그인
  • 새 비밀번호는 8~16자 영문·숫자·특수문자 조합
  • 경로: 우측 상단 소속 정보 클릭 > 비밀번호 변경
  • 로그인 전에도 로그인 화면의 비밀번호 변경에서 아이디 입력 후 변경 가능
계정이 잠겼다면?
  • 비밀번호 연속 5회 오류 시 계정 잠김
  • 비밀번호가 기억나지 않으면 임시비밀번호 발급 기능 사용
  • 로그인 화면에서 임시비밀번호를 발급하면 재설정되며 잠금 해제
  • 직접 처리가 안 되면 IT지원실에 잠금 해제 요청
계정·소속이 이상하면 누구에게?
  • 계정과 부서·팀 정보는 HRMS에서 연동됨
  • 뉴인트라넷에서 계정 생성·소속 변경은 불가
  • 이름·소속·겸직이 다르면 인사담당자·인사팀에 HRMS 확인 요청
  • 메뉴·버튼만 안 보이면 권한 문제
임시비밀번호 메일이 안 오면?
  • 시간강사는 개인 이메일, 그 외는 회사 이메일로 발급됨
  • 이메일 주소가 다르면 인사담당자 또는 IT지원실에 확인 요청
  • 개인 이메일로 받는 경우 스팸함 확인
초기 비밀번호와 계정은 어떻게 생기지?
  • 초기 비밀번호는 생년월일 8자리(예: 19900101)
  • HRMS 입사·위촉 → 뉴인트라넷 계정 자동 생성
  • HRMS 퇴사·해촉 → 계정 사용 중지
  • HRMS 겸직·이동·발령 → 소속 정보와 데이터 조회 권한 변경
  • 별도 가입 불필요, 계정이 안 보이면 인사담당자·인사팀에 HRMS 처리 확인

  • 비밀번호 5회 오류 전에 임시비밀번호 발급 사용

문의 DB 더블(중복) 조회

  • 4숫자를 클릭하면 중복 DB 목록 조회
  • 숫자가 없으면 중복 없음
자동 검사는 언제 돌지?
  • 더블 검사는 30분 간격으로 자동 실행(FAQ 답)
  • 원문 개요에는 하루 한 번으로 적혀 있어 표기가 서로 다름
  • 즉시 확인이 필요하면 [더블수동검사] 사용

  • 아니오
  • 선택한 지점과 관리자가 설정한 비교 범위 기준으로 전체 문의DB를 검사
언제 수동검사를 쓰지?
  • 신규 DB를 등록한 직후 중복을 바로 확인할 때
  • 다음 자동 검사를 기다리지 않아도 됨
중복 판단 기준은 무엇이지?
  • 더블조회설정: 어떤 계열의 DB끼리 비교할지
  • 더블조회조건설정: 이름·전화번호·전화번호 뒤 4자리·IP 중 선택
  • 선택한 조건이 모두 일치해야 더블로 판단
  • 설정은 사업관리 > 문의DB배정관리 > 문의DB더블검색설정(관리자)
중복이 안 잡히면?
  • 조건을 너무 엄격하게 선택했는지 확인
  • 조건이 많을수록 모두 일치해야 하므로 판정 범위가 좁아짐
  • 이름+전화번호 또는 이름+전화번호 뒤 4자리 조합 검토 가능
  • 기준 저장 후 초기화에 수분 소요, 즉시 반영 안 될 수 있음
  • 문의DB더블검색설정에서 해당 계열의 판단 조건 확인
  • 조건 일부가 아니라 선택 항목 전부 일치해야 더블
  • IP Address가 조건이면 이름·전화번호가 같아도 IP가 다르면 더블 아님
  • 기준 변경 후 데이터가 많으면 재판단에 시간 소요, 백그라운드 작업 후 완료 시 갱신

헷갈리는 점

  • 더블수동검사는 권한이 있는 경우만 사용
  • 기준을 바꾸면 모든 문의DB를 새 기준으로 다시 확인
  • IP까지 선택하면 IP가 다를 때 더블로 안 잡힘

요약더블수동검사로 전체 DB의 중복을 즉시 확인하고, 안 잡히면 판단 조건이 지나치게 엄격한지 본다.

  • 기존 결제 부분 취소 불가, 결제 건별 전체 취소만 가능
  • 공제금 먼저 결제 후 기존 결제건 취소
  • 1수납내역 우측 상단 [결제등록]
  • 2공제금 금액 입력, '공제금' 반드시 체크
  • 3결제수단·정보 입력 후 [결제진행]

결제수단별 입력 방법은?
  • SPC 카드·현금/계좌이체 연계등록: 환불방식 선택 필수
  • 수기 입력: 카드사에 상계/회입 문의 후 유선 처리 완료한 경우, 상계/회입 입력
  • 단말기 연계: 단말기로 환불, 카드는 자동 상계
  • 자체입력(SPC·PG 카드, SPC 현금/계좌이체): 환불 완료 후 환불구분 입력
  • 페이민트: 연계등록은 자동 환불 요청, 자체입력은 완료 후 입력
  • 계산서발행·지역화폐/상품권·페이머니·PG(현금)·국비매출: 완료 후 정보 저장
  • 회입/상계·수수료는 카드사에 전화해 직접 확인
[환불 진행]을 누르면 무엇이 처리되지?
  • SPC(섹터9) 카드 단말기연계: 단말기에서 카드 취소 진행
  • SPC(섹터9) 현금/계좌이체 단말기연계: 단말기에서 현금 취소 진행
  • 페이민트(결제선생): 결제선생에 취소 요청, 자동 처리

  • 매출로 집계되지 않고 환불 금액 계산에만 사용
  • 하나의 공제금에 여러 기존 결제건 연결 가능

  • 예: 50만 원 2회 결제, 공제금 70만 원 → 실 환불 100만-70만=30만 원
  • 한 건이라도 연결이 빠지면 환불 금액 오계산
공제금은 어떻게 마감하고 확인하지?

  • 선수금 연결 내역 팝업에서 연결 결제건 확인
  • 연결 상태를 연결 중에서 마감으로 변경 후 [저장]
  • 마감한 공제금은 선수금 목록에서 사라짐
  • 되돌리기는 연결 중으로 변경 후 저장, 해당일 환불 전표 전송 뒤에는 불가
  • 마감 전에는 환불 전표 작성 불가
  • 확인: 운영관리 > 환불관리 > 환불선수금현황 > 계열·지점·매출기간·학생이름 조회, 마감여부 '연결중' 확인
교보재·재료비·온라인강좌 환불은?
  • 수강생현황 > [교보재/재료비] 또는 [온라인강좌] 탭, 방법 동일
  • 결제 그룹 단위로 환불 가능
  • 그룹 일부만 환불하면 남길 금액을 공제금으로 결제 후 전체 환불
  • 공제금 처리도 각 탭에서 같은 방법
  • 온라인 강의도 같은 환불 화면에서 처리

헷갈리는 점

  • 기안 최종 승인 전에는 실제 환불 불가
  • 부분 환불은 공제금 결제 후 기존 결제 전체 환불 순서
  • '공제금' 체크를 빠뜨리면 일반 결제(매출)로 집계, 선수금 목록에도 안 뜸
  • 마감하지 않은 공제금이 있으면 환불 전표 작성 불가
  • 자체입력 결제는 실제 취소 후 기록

요약기안 승인 뒤 입금정보에서 결제건을 전체 환불하고, 부분 환불은 공제금을 먼저 결제해 연결한 뒤 마감한다.

이벤트는 어떻게 등록하나?

  • 재고 수량 기준으로 등록 수량 결정, 대상·지급 방법 선택

  • 등록 수량은 상품 가용재고 기준
  • 시작일이 도래하지 않은 이벤트만 수정 가능
  • 지급·수령 이력이 있으면 이벤트 삭제 불가

  • 하단 [저장]

  • 출고는 수기로 입력할 수 없음
  • 이벤트로 상품이 지급되면 지급출고로 자동 출고, 지급 내역은 지급관리에서 조회
  • 지급이 아닌 사유(폐기·분실)로 재고가 줄면 재무팀에 문의
  • 입고는 아이템관리에 상품이 먼저 등록돼 있어야 함

  • 가용재고: 지금 바로 쓸 수 있는 재고
  • 예약재고: 이벤트에 배정됐거나 미지급·지급 대기·수령 대기인 수량
  • 지급·수령 완료 시 예약재고에서 실제 출고로 이동
  • 이벤트 종료 뒤 지급 대상자로 등록 안 된 배정 수량은 자동으로 가용재고 복귀, 다른 이벤트에 재배정 가능

  • 입고 유형: 신규·반품·이동·기타입고
  • 출고 유형: 지급·이동·폐기·기타출고
  • 수불관리는 흐름 확인용(예: 이번 달 문화상품권 입고·지급 수량)
  • 수불관리의 입고 유형은 입고 메뉴에서 등록·수정 시 변경, 출고는 지급 시 자동 기록
